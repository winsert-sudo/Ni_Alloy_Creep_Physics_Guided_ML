# Summary interpretation and disclosure boundary

These files are inspected PUBLIC aggregate results, not experimental rows. Model/analysis names, counts and error metrics may be joined across summaries; there are no actual experimental record/state identifiers, condition arrays, targets, predictions or residuals in these summaries. Source-group IDs occur only in the metadata-only register with no numerical linkage. Numeric summary cohorts contain at least 139 observations (the supported physics subset); no small-cell, per-source, per-state or per-fold metric rows are admitted.

Multiple cohort summaries can constrain aggregate error moments or target variability. They do not determine individual temperatures, stresses, life values, compositions or source-record identities. In particular, R2 and RMSE may reveal aggregate target variance; that disclosure is not represented as zero information leakage. There is no actual target/prediction vector to resolve individual rows. Duplicate cohort summaries do not supply additional per-record equations.

The PUBLIC 186-row reconstruction-metric file is conservatively withheld because a byte-identical sibling is CONDITIONAL in the matrix. Source-specific database version/audit metadata is also excluded. Previously frozen top-level descriptive/oracle metric statements in HEADLINE_NUMBERS.md are retained as approved aggregate summaries, with distinct estimands and no state-linked coefficients.

Recorded configuration paths identify absent input types, not bundled datasets. Historical benchmark Python/platform values in unified_benchmark_run_config.json are retained as recorded history and distinguished from the reconstructed publication environment. Scientific model settings, seeds, metrics and decimal spelling in copied tables remain unchanged.

FROZEN_RESULTS.md describes a prior internal reproduction; candidate construction does not repeat it. Candidate file checksums are integrity checks only. Reviewed code defines computations but supplies no fitted model, data vectors or trained parameters. See [reverse leakage audit](../docs/RELEASE_CONTENT_SCOPE.md) for joint-file checks and their limits.
